# MicroLend — screenshot capture plan

**Owner:** `docs-qa` · Referenced by `docs/REPORT.md` §9 and the rubric row *Frontend User Interface*.

## Status in this environment (read this first)

**No browser screenshots were captured.** This environment has no browser automation (no Playwright /
Puppeteer / Selenium) and no display, and there is no funded Sepolia wallet, so the interactive UI,
MetaMask prompts and a deployed contract on Etherscan **cannot be captured here**. Nothing in this
repository pretends otherwise: no placeholder images are committed, and any screenshot you see that
looks like a UI must have been produced by the person running the steps below on their own machine.

What *does* exist, and is reproducible by anyone:

| File | What it is | How it was produced (real, re-runnable) |
|---|---|---|
| [`docs/images/architecture.png`](images/architecture.png) | system architecture diagram | `python docs/images/gen_diagrams.py` (Pillow, programmatic — not a screenshot) |
| [`docs/images/money-invariant.png`](images/money-invariant.png) | before/after money-identity measurement chart | same script; the plotted numbers are the wei-exact results of the ganache runs recorded in `docs/TESTING.md` §5.2 |
| `docs/images/gen_diagrams.py` | the generator for the two files above | ships with the repository so the figures can be regenerated byte-for-byte |

`docs/TESTING.md` holds the raw textual evidence (compile output, gas table, 45-check custom-error
matrix, endpoint matrix). A console transcript is acceptable evidence for *Testing and Results*; the
assignment's §VIII screenshot requirement is about the **running application**, so the interactive
captures below still need to be produced on a machine with a browser and (for Etherscan) a real
Sepolia deployment.

## Prerequisites for every interactive capture

```powershell
# from the repository root
node scripts/dev-chain.js          # or use Sepolia in MetaMask
node scripts/compile.js
node scripts/deploy-local.js       # prints the deployed address
python -m http.server 8080 --directory frontend     # then open http://127.0.0.1:8080/
```

For the offline captures (S2–S5) nothing else is needed: with no contract address configured the app
starts in **demo mode** (force it with `?demo=1`), and the whole protocol runs in the browser. For the
wallet captures (S1, S6) you need MetaMask with the Sepolia network (`0xaa36a7`) and a little test
ETH.

Capture tool: **Win + Shift + S** (Windows Snipping Tool) saves to the clipboard, then paste into
`docs/images/`. Save with exactly the filenames below so that `docs/REPORT.md` references stay valid.

## Required alternative for a marker with no wallet

Because S1/S6 need a real wallet/testnet, the report also leans on the **offline demo mode** (S2–S5,
S7). The claim "the DApp works" can therefore be checked in about a minute:

```powershell
python -m http.server 8080 --directory frontend
# open http://127.0.0.1:8080/?demo=1  -> deposit -> borrow -> repay -> history
```

## Consistency checks before submitting screenshots

1. Every screenshot must come from the **same revision** as `contracts/MicroLendPool.sol`
   (sha256 `e26e720a9c2eb75175679abb4a9f71cb403cfd466d3cd99fe547df8131964657` at the time of writing);
   the app's top bar shows a build label for exactly this reason.
2. Numbers visible in a screenshot must agree with `docs/TESTING.md` (e.g. the 10 % fee split and the
   simple-interest formula) — if they do not, the screenshot is from an older build; retake it.
3. Never submit a mock-up, a cropped image whose transaction hash cannot be resolved, or a screenshot
   of demo mode labelled as a Sepolia transaction. Demo mode is explicit in the UI; keep it that way.
